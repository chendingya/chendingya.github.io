# 需求文档

## 1. 项目概述

**项目名称**：AI Blog  
**项目目标**：构建一个将Markdown文件转换为静态HTML页面的个人博客系统，主要部署在GitHub Pages等免费静态托管平台。

## 2. 功能需求

### 2.1 核心功能
- **Markdown转HTML**：将指定文件夹中的Markdown文件转换为静态HTML页面。
- **模板系统**：支持自定义HTML模板，包括头部、导航、页脚等公共部分。
- **文章元数据**：支持YAML front matter，包含标题、日期、标签、分类、作者等信息。
- **文章列表**：自动生成按时间排序的文章列表（首页）。
- **分页**：支持文章列表分页（可选）。

### 2.2 图片处理
- **图片优化**：自动压缩图片，支持WebP等现代格式。
- **响应式图片**：生成多种尺寸的图片，使用`srcset`和`sizes`属性。
- **图片懒加载**：默认启用懒加载，提升页面加载速度。
- **图片存储**：支持本地图片和外部URL图片。

### 2.3 UI设计
- **主题系统**：支持更换主题，或自定义CSS样式。
- **响应式设计**：适配桌面、平板、手机等不同屏幕尺寸。
- **暗色模式**：支持自动切换或手动切换暗色/亮色模式。
- **代码高亮**：支持Markdown代码块的语法高亮。
- **目录生成**：自动生成文章目录（TOC）。

### 2.4 博客功能
- **关于页面**：支持自定义关于页面，展示个人信息。
- **友链页面**：支持友情链接页面，可配置友链列表。
- **标签/分类**：支持文章标签和分类，并能生成标签/分类页面。
- **归档页面**：按年月归档文章。
- **RSS订阅**：生成RSS feed（可选）。

### 2.5 部署与配置
- **GitHub Pages兼容**：生成的静态文件可直接部署到GitHub Pages。
- **配置文件**：支持通过配置文件（如`config.yml`或`config.json`）设置站点标题、描述、作者、主题等。
- **构建脚本**：提供简单的构建命令，如`npm run build`。
- **本地预览**：支持本地开发服务器，实时预览更改。

## 3. 非功能需求

### 3.1 性能
- **构建速度**：对于100篇文章，构建时间应在10秒以内。
- **页面加载**：生成的页面应优化加载速度，符合Core Web Vitals标准。
- **图片优化**：图片应经过压缩，减少页面体积。

### 3.2 可维护性
- **代码结构**：清晰的代码结构，易于理解和扩展。
- **文档**：提供详细的使用文档和开发文档。
- **测试**：核心功能应有单元测试覆盖。

### 3.3 兼容性
- **浏览器兼容**：支持现代浏览器（Chrome、Firefox、Safari、Edge）。
- **Markdown兼容**：支持CommonMark和GFM（GitHub Flavored Markdown）规范。

## 4. 用户故事

### 4.1 作为博主，我希望：
1. 将Markdown文件放入`posts`文件夹，运行构建命令后生成完整的博客网站。
2. 通过修改配置文件轻松更改博客标题、描述和主题。
3. 在Markdown文件中使用YAML front matter设置文章标题、日期、标签等。
4. 自动生成响应式图片，无需手动处理不同尺寸。
5. 轻松添加关于页面和友链页面。
6. 将生成的网站部署到GitHub Pages，无需服务器。

### 4.2 作为读者，我希望：
1. 在手机上流畅阅读博客文章。
2. 通过标签或分类快速找到相关文章。
3. 订阅RSS feed获取更新（可选）。

## 5. 技术约束

- **运行环境**：Node.js 16+（推荐使用LTS版本）。
- **部署平台**：GitHub Pages（主要），也支持其他静态托管服务。
- **许可证**：MIT许可证。

## 6. 范围与限制

### 6.1 范围
- 仅生成静态HTML页面，不包含后端服务。
- 不支持动态内容（如评论系统），但可集成第三方评论服务（如Disqus）。
- 不支持用户登录/注册功能。

### 6.2 限制
- 图片处理可能需要额外依赖（如Sharp），在某些环境下安装可能复杂。
- 构建时间取决于文章数量和图片处理复杂度。

## 7. 验收标准

1. 能够将`posts`文件夹中的Markdown文件转换为HTML页面。
2. 生成的页面包含正确的元数据、样式和脚本。
3. 图片经过优化，支持响应式加载。
4. 支持至少一个主题，并可自定义样式。
5. 能够部署到GitHub Pages并正常访问。
